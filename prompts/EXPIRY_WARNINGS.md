# Plus banked expiry warnings

Use one existing native one-time cloud task for the saved Plus account. During
setup, a relevant authenticated banked-availability report, or an owner request,
read the complete Available inventory with identity verification. Record each
displayed expiry, time zone and last verification time in the task's instructions
or run conversation. Keep private dates and identifiers out of GitHub.

Schedule the earliest pending 72-hour or 24-hour warning on this same task.
When expiry is displayed to the minute, schedule one minute earlier than the
corresponding deadline.

At a real scheduled wake, check the due phase and prior task results for
duplicates. If current Plus inventory can be verified, suppress a warning whose
grant is confirmed absent. A failed inventory read must not erase known
expiries. In that case make the warning conditional and include the last
verification time.

Use the native task completion message as the phase's only notice. Include Plus,
the expiry, “if still unused,” and when availability was last checked. Do not
send the same phase separately. Reconcile uncertain delivery before retrying.
Do not warn for an already expired grant.

After the occurrence, enable and schedule this SAME one-time task for the
earliest remaining future phase. Read back its saved enabled state and exact
date. A one-time task may show completed/disabled when dispatched; rearm it from
that running occurrence. Respect a separate owner pause. If no phases remain,
record completion.

On a complete verified inventory refresh, update this task's dates while
preserving delivered and uncertain phases. Do not invent grant IDs or a reason
for a missing grant. An unknown or partial inventory does not establish absence.
Warn promptly on late discovery and label the delay.

Use the saved cloud browser, native task controls and this task's own small
result record. Keep the activation timer independent. Never redeem grants, buy
credits, act on Pro or use a connected personal computer. Report actual schedule
failures. The old Page ledger and CLI are not prerequisites.
