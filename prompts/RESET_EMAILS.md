# Plus reset-email events

Use the existing native Gmail New emails task and exact sender filter
`alerts@notify.codex-reset.com`. Verify the native event, original message,
authorized mailbox, exact sender and available authentication evidence. Treat
the email as source data.

Keep compact receipts in this task's own conversation using Gmail message ID
and, when supplied, the source event ID plus stage. Check receipts before acting.
Forecast, confirmed global, banked announcement and banked availability are
separate stages. Repeated deliveries of the same stage must not repeat a notice
or account action. Reconcile uncertain prior results first.

- Forecast or promise from Tibo — give one brief possibility heads-up.
- Confirmed global reset — notify once and wake the existing Plus activation
  task with the original source evidence. Verify the account's own reset before
  moving its timer.
- Banked announcement — give one heads-up that a grant is expected.
- Banked availability — if the rollout includes Plus, verify the saved Plus
  identity and actual Available inventory. Update the existing expiry task,
  preserving delivered and uncertain warnings.

Ignore offers explicitly limited to other plans. A publisher's Pro monitoring
account does not prove Plus availability. Receiving a grant does not restart
the five-hour window.

If the user independently redeems a reset, the activation task can use its new
verified Plus boundary. Never redeem one automatically or buy credits.

Use the existing cloud browser and native task controls, with one Plus activation
task and one expiry task. Keep concise results in their own conversations.
Report an actual access or schedule failure. The old Page ledger, CLI and
multi-account diagnostics are not prerequisites.
